# ADR 0008: GitHub API呼び出しは403/429を`Retry-After`に従って一度だけリトライする

## Status

Accepted

## Date

2026-09-11

## Context

GitHubはセカンダリレート制限・不正利用検知の両方を`403`(`429`だけではない)で返すことがある。
mise-bump-actionは1回の実行あたり数件〜十数件程度のAPI呼び出ししか行わないため、恒久的な
レート制限超過は想定しにくく、無限リトライやバックオフの複雑な実装は過剰である。

## Decision

`internal/githubapi.Client.do`は、レスポンスが`403`または`429`かつ`Retry-After`ヘッダーを
含む場合に限り、そのヘッダーの秒数だけ待って一度だけ再試行する。2回目の失敗はそのまま
呼び出し元にエラーとして返す。

## Rules

- リトライは1回のみ。ループでの無限リトライは行わない。
- `Retry-After`ヘッダーが無い403/429は一時的なレート制限とみなさず、即座にエラーにする。
- リトライ対象は403/429のみ。5xx等その他のエラーはリトライしない。

## Consequences

- 一時的なレート制限は自動的に回復するが、恒久的な制限超過やアクセス権限不足による403は
  1回の遅延の後にそのままエラーとして表面化する。
- 複雑な指数バックオフや無限リトライを実装しない分、コードは単純だが、
  想定より重いワークロード(多数のmise-config-pathを同時に処理する等)では
  リトライ回数の見直しが必要になる可能性がある。
